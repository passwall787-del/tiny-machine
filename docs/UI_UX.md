# UI / UX 规范

## 1. 总原则

手机端优先。任何桌面端方便但手机端困难的交互都需要重新设计。

## 2. P0 顶部栏

当前顶部栏包含：

- 游戏标题
- 操作提示
- 组件添加按钮
- 开始/暂停
- 重置

## 3. 对比度要求

此前 P0 存在“按钮颜色与背景过于接近”的问题，已作为正式设计规则记录：

- 功能按钮必须与背景形成明显明度差。
- 主要操作必须有独立强调色。
- 文本必须保持高对比度。
- Disabled 状态必须仍然可识别，而不是简单降低到接近背景色。
- 不得仅依赖颜色区分状态，应同时使用文字、图标或形状。

## 4. 当前颜色角色

当前不是最终视觉规范，但角色应保持：

| 角色 | 用途 |
|---|---|
| Dark Background | 游戏背景 |
| Dark Panel | UI 面板 |
| Blue Accent | 主操作 |
| Light Text | 主要文字 |
| Muted Text | 辅助说明 |
| Green | 目标/成功 |
| Orange/Brown | 木质机关 |
| Cyan | 选中高亮 |

未来可把这些颜色集中为 Theme Resource。

## 5. 触摸交互

### 拖动

- 按住组件开始拖动。
- 手指移动时组件跟随。
- 松手后停止拖动。
- 组件必须被限制在有效游戏区域。

### 选择

选中的组件需要明显高亮，避免玩家不知道当前操作对象。

### 缩放

P2 可增加双指缩放游戏区域。缩放后必须保证 UI 不随世界缩放。

### 旋转

P1 建议支持：

- 双指旋转；或
- 选中后显示旋转手柄；或
- 独立旋转按钮。

优先测试独立旋转按钮，因为它对新用户最容易理解。

## 6. 可点击区域

手机端按钮不要只让文字本身可点击。按钮实际点击区域应该明显大于文字。

## 7. 状态反馈

每个重要状态至少通过两种方式表达：

```text
运行中 = 按钮文字 + 状态文字
成功 = 目标动画 + 成功文字
暂停 = 按钮文字 + 状态文字
选中 = 高亮轮廓 + 状态
```

## 8. 安全区域

正式 Android 版本必须考虑：

- 刘海
- 状态栏
- 导航栏
- 横屏安全区
- 不同宽高比

不要硬编码“所有设备都是 1280×720”。P0 的 1280×720 只作为设计画布。

## 9. 可访问性

未来版本考虑：

- 更大的文字模式
- 色觉友好
- 触觉反馈
- 音效提示
- 高对比度主题

## 10. UI 验收

每次 UI 修改至少在：

- 720p 模拟器
- 常见 1080p Android 手机
- 高宽比 Android 手机

检查按钮是否可见、可点、无遮挡。
