# UI / UX 规范

## 1. P3.1 视觉目标

Tiny Machine 现在从“功能原型界面”进入“可长期游玩的移动游戏界面”。视觉关键词：

- 机械工作台 / 工坊。
- 清晰的施工区、零件仓库、发射按钮三分结构。
- 零件有明显材质、阴影、轮廓和状态反馈。
- 所有主要操作保持高对比度、大触摸区域。

这种“主施工区 + Parts Bin + Run”结构也符合这一类机械连锁解谜游戏的经典交互模型：玩家从零件仓库取出组件放到施工区，调整后启动机器。citeturn6search12turn6search3

## 3. 关卡初始状态

官方关卡进入时：

- 施工区没有玩家可编辑零件。
- 小球作为固定的“发射源”显示在 START 位置，不属于零件库存。
- 目标区固定显示。
- 所有可用组件进入下方零件仓库，并显示剩余数量。
- 玩家点击零件仓库添加组件。
- 添加后组件自动出现在施工区并选中，随后可以拖动和旋转。
- 至少添加一个零件后，`▶ 发射小球` 才可用。

## 4. 按钮对比度

- 主操作：高亮蓝色。
- 普通操作：独立深色面板 + 明显边框。
- 零件仓库：卡片化按钮 + 独立图形图标 + 数量徽标。
- Disabled：降低亮度，但保留轮廓和文字可读性。
- Pressed：边框加粗。

Godot 的 StyleBoxFlat 支持圆角、边框和阴影，当前 UI 使用这些能力统一处理按钮和面板视觉层级。citeturn11search0

## 5. 编辑 / 运行

编辑状态：

- 组件可拖动。
- 组件有选中高亮。
- 可以旋转、多选、删除、撤销、重做、网格吸附。
- 零件仓库显示剩余数量。
- 小球不可编辑，只作为启动源。

运行状态：

- 玩家组件不能拖动。
- 零件仓库和编辑工具锁定。
- `▶ 发射小球` 变为 `⏸ 暂停`。
- 小球进入目标区后立即结束模拟。

## 6. 组件视觉

每个组件必须有可识别的独立轮廓：

- Board：木材、纹理、铆钉。
- Slope：木质斜面、边缘高光。
- Spring：金属底座、线圈和方向箭头。
- Rope：绳股纹理、剪断状态。
- Scissors：刀刃 + 手柄。
- Gear：齿形、中心轴、旋转状态。
- Switch：ON / OFF + 拨杆。
- Balloon：高光 + 绳线。
- Magnet：红蓝极性 + 吸引反馈。
- Bomb：球形外壳 + 引线 + 火花。
- Ball：高光、轮廓、发射起点阴影。

## 7. 目标反馈

目标区持续显示：

- 绿色外圈。
- 内部光晕。
- TARGET 标签。
- 轻微呼吸动画。

成功后目标区变亮并配合通关面板动画。

## 8. 手机可读性

避免：

- 小于 11px 的关键文字。
- 低对比度文字。
- 过细边框。
- 需要精确点击 1~2 px 的按钮。
- 把多个功能塞在同一个低对比度按钮里。

自定义绘制适合当前这类大量简单 2D 组件与网格的场景，可以减少额外节点并保持视觉一致性。citeturn10search4
