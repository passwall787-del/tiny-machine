# 测试计划

## 1. P0 验收

### 启动

- [ ] APK 可以安装。
- [ ] APK 可以启动。
- [ ] 横屏显示正常。
- [ ] 无明显启动错误。

### UI

- [ ] 顶部按钮清晰可见。
- [ ] 主按钮与背景有明显对比。
- [ ] 开始按钮可以点击。
- [ ] 重置按钮可以点击。
- [ ] 添加组件按钮可以点击。
- [ ] 状态文字不会被遮挡。

### 编辑

- [ ] 小球可以拖动。
- [ ] 木板可以拖动。
- [ ] 斜坡可以拖动。
- [ ] 组件不会被拖出有效区域。
- [ ] 松手后组件停止拖动。

### 运行

- [ ] 点击开始后小球开始受重力影响。
- [ ] 编辑组件按钮在运行中不可用。
- [ ] 暂停能够冻结模拟。
- [ ] 继续能够恢复模拟。
- [ ] 重置能够恢复初始状态。

### 第一关

- [ ] 默认布局可以成功完成。
- [ ] 小球能够从第一段斜坡进入后续路径。
- [ ] 不会因为斜坡方向错误而掉出路线。
- [ ] 小球能够进入目标区域。
- [ ] 成功状态显示正确。

## 2. 回归测试

每次修改物理代码后重新测试：

1. 默认关卡成功。
2. 拖动小球后重置。
3. 拖动斜坡后重置。
4. 连续运行/暂停 10 次。
5. 连续成功/重置 10 次。

## 3. Android 真机矩阵

至少测试：

- 一个中端 Android 手机。
- 一个高端 Android 手机。
- 一个小屏设备。
- 一个高宽比设备。

如果只能测试一台设备，必须至少覆盖 ARM64 Android。

## 4. 性能

目标：

- 简单关卡 60 FPS。
- 无明显掉帧。
- 运行 5 分钟无持续内存增长。
- 手机不过度发热。

P1 加入复杂机关后再建立正式性能基线。

## 5. 物理一致性

同一 APK、同一初始状态连续运行至少 20 次，结果应一致。

如果出现随机成功/失败，优先检查：

- 初始速度
- sleeping 状态
- collision shape
- 物理时间步
- 组件初始化顺序

## 6. 发布前检查

- [ ] `main` 构建成功。
- [ ] APK SHA-256 已记录。
- [ ] 已知问题已记录。
- [ ] Debug/Release 状态明确。
- [ ] 没有提交 secrets。
- [ ] README 与实际功能一致。
