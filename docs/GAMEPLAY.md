# 游戏规则

## 1. 基本规则

每个关卡提供：

- 初始场景
- 玩家可使用的组件集合
- 一个或多个目标条件
- 可选的操作限制

玩家进入编辑状态后摆放组件。点击开始后，物理模拟运行，玩家不能改变受运行影响的组件。

## 2. 当前 P0 规则

P0 只有一个目标：**让小球进入绿色目标区域。**

成功条件：

```text
ball 与 Target Area 发生有效 body_entered
AND
当前状态为 RUNNING
```

成功后：

- `won = true`
- 停止模拟
- 小球冻结
- 开始按钮变为“✓ 完成”
- 显示成功信息

## 3. 游戏状态

推荐正式版本使用以下状态机：

```text
EDITING
   │
   ├── Start ──→ RUNNING
   │               │
   │               ├── Pause ──→ PAUSED
   │               │                │
   │               │                └── Resume ──→ RUNNING
   │               │
   │               └── Goal satisfied ──→ SUCCESS
   │
   └── Reset ──→ EDITING

RUNNING/PAUSED/SUCCESS
   └── Reset ──→ EDITING
```

未来可增加 `FAILED`，但失败不应该因为单个物体离开屏幕就立即触发；应该由关卡定义失败条件。

## 4. 编辑模式

编辑模式允许：

- 选择组件
- 拖动组件
- 旋转组件（P1）
- 删除组件（P1）
- 添加组件
- 撤销/重做（P2）

编辑操作不能直接改变已锁定的运行状态。

## 5. 运行模式

运行模式下：

- 物理系统拥有组件位置。
- 玩家不能移动普通物理组件。
- 暂停应冻结物理时间。
- 重置应恢复所有组件初始位置、旋转和物理速度。

## 6. 重置规则

重置必须恢复：

- position
- rotation
- linear velocity
- angular velocity
- sleeping/freeze 状态
- 临时机关状态
- 目标状态
- 计时器
- 运行状态

P1 之后每个组件都必须实现统一的 `reset_state()` 接口。

## 7. 解题原则

一个关卡应该有至少一个稳定解。所谓稳定解是指：

- 不要求像素级操作。
- 不依赖极端浮点误差。
- 不依赖随机初始速度。
- 在目标平台支持的帧率范围内可以重复成功。

## 8. 关卡失败

失败的定义必须来自关卡设计，而不是简单使用“运行 N 秒没有成功”。建议未来使用：

- 所有目标物离开有效区域。
- 必要物体进入不可恢复状态。
- 计时器结束。
- 任务明确要求的资源耗尽。

## 9. 暂停与调试

正式版本建议暂停时保留：

- 当前物理位置
- 当前速度
- 当前机关状态
- 当前模拟时间

P2 可增加单帧前进、时间轴和回放。
