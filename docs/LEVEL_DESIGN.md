# 关卡设计规范

## 1. 关卡结构

每个正式关卡应包含：

- `id`
- `title`
- `difficulty`
- `available_components`
- `initial_components`
- `goals`
- `constraints`
- `recommended_solution`
- `validation_notes`

## 2. 关卡目标

目标应该尽量一句话说清楚，例如：

> 让红球进入右侧目标框。

复杂关卡可以组合目标：

> 让两个球分别进入两个目标，并在 10 秒内完成。

## 3. 难度曲线

建议：

```text
Tutorial
  ↓
单一机制
  ↓
两个机制组合
  ↓
时序问题
  ↓
多目标
  ↓
资源限制
  ↓
复杂连锁
```

不要一开始同时引入多个新机制。

## 4. P0 第一关

目的：验证最基本的“坡面导向”。

组件：

- 1 × Ball
- 3 × Slope
- 1 × Board
- 1 × Target

设计要求：

- 玩家不需要旋转组件即可完成。
- 路径必须明显可见。
- 小球应从左上向右下运动。
- 目标位于右下区域。
- 允许一定的位置误差。

## 5. 可解性验证

每关发布前必须完成：

### A. 人工验证

- 从默认布局开始能成功。
- 移动一个组件后仍能理解问题。
- Reset 后可以重复成功。

### B. 物理验证

- 无明显穿透。
- 无随机失败。
- 无明显卡死。
- 无依赖设备帧率的行为。

### C. Android 验证

- 手指拖动准确。
- UI 不遮挡关键区域。
- 不存在安全区域/刘海遮挡。
- 触摸后释放不会继续拖动。

## 6. 解答记录

每个关卡应该保留开发者解答说明，但不直接展示给玩家：

```text
Solution:
1. 球保持默认位置。
2. 第一段斜坡承担落差。
3. 第二段斜坡修正水平位置。
4. 最后一块板将球送入目标。
```

## 7. 关卡数据化计划

P1 仍可以使用 GDScript 构建关卡，但 P2 应改为 JSON/Resource：

```json
{
  "id": "level-001",
  "components": [
    {"type":"ball","position":[310,155]},
    {"type":"slope","position":[350,300],"rotation":0.30}
  ],
  "goals": [
    {"type":"ball_enter_area","target":"target-1"}
  ]
}
```

## 8. 关卡验收标准

一个关卡只有在以下条件全部满足后才能进入 release：

- 至少一个可靠解。
- 关键操作不要求像素级精度。
- 新手能理解目标。
- 失败原因可观察。
- Reset 后状态干净。
- Android 真机验证通过。
