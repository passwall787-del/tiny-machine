# 关卡设计规范

## 1. 核心目标

关卡的本质是：

> 玩家利用有限组件建立一套可重复运行的机械连锁反应，并让目标对象进入目标区域。

## 2. P1 关卡结构

每个关卡至少定义：

- level_id
- level_name
- goal_object
- target_position
- fixed_components
- player_components
- success_condition
- optional failure_condition

## 3. 终端通关

P1 明确采用：

```text
目标对象进入 Target
        ↓
立即判定成功
        ↓
立即停止模拟
```

不能让玩家继续修改或继续观察已经成功的物理状态。

## 4. 稳定解

一个有效解必须满足：

- 至少两次连续运行均成功。
- 不要求像素级放置。
- 不依赖极端碰撞角度。
- 不依赖某一帧的随机接触。
- 设备帧率变化不会改变解题逻辑。

## 5. P1 难度曲线

### Level 01

只学习：

- 重力。
- 斜坡。
- 碰撞。
- 目标区。

### Level 02

引入：

- Switch。
- Gear。
- Spring。
- Rope / Scissors。
- Balloon。

目标是让玩家第一次理解“一个机关触发另一个机关”。

## 6. 组件数量

不要为了展示所有组件而强行加入关卡。组件必须对解法有意义，或者作为明确的教学/实验对象存在。

## 7. 视觉提示

机关在编辑状态必须能看出：

- 放在哪里。
- 大致作用方向。
- 是否有方向性。
- 是否处于已触发状态。

## 8. 失败

P1 不自动把“没有成功”定义为失败。

未来失败必须来自关卡规则，例如：

- 必要物体离开区域。
- 资源耗尽。
- 定时器结束。
- 不可恢复状态。

## 9. 回归要求

任何物理系统修改都必须重新验证：

- Level 01。
- Level 02。
- Reset。
- Pause / Resume。
- Target immediate stop。
- Android touch。
